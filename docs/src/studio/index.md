# Exegol Studio overview <Badge type="new"/>

Exegol Studio is an Integrated Hacking Environment (IHE): a hacking cockpit for VS Code and compatible forks (Cursor, Windsurf, VSCodium, and others). It runs on top of [Exegol Workstation](/workstation/).

![](/assets/studio/overview.png)

## Learn from it

Exegol Studio lowers the gap between *"I know what to run"* and actually running it, reading the output, and keeping a path:

- [Monitor](/studio/interface/layouts#the-three-layouts) layout: watch each command and its raw output as it runs
- [Mentor](/studio/behavior/personas) persona: explains the why while it works
- [Approvals](/studio/behavior/approvals): keep you in the loop until you trust the policy
- [Speed](/studio/interface/composer#quick-settings) to the minimum: to slow down the paint so a walkthrough stays followable

## Teach it

A generic model knows about as much about chaining unauth recon into an account takeover as it does about the torque on your front wheel, and that is probably optimistic. It does not know your scope, your lab habits, or the tools you already live in. Teaching Studio is what makes the brain useful on *your* engagements instead of a clever stranger guessing.

**Make the harness relevant.** [Skills](/studio/knowledge/skills), [rules](/studio/knowledge/rules), [agents](/studio/knowledge/agents), [hooks](/studio/knowledge/hooks), and [briefs](/studio/knowledge/briefs) are how you encode methodology: what to try first, what never to touch, how to report, when to stop. Use the [Atlas](/studio/knowledge/atlas) to wire efficient knowledge to the model's brain. Without all that, the model improvises. With it, every turn starts closer to how you would work. That is the difference between babysitting a chat and running a controllable cockpit.

**Wire [MCPs](/studio/knowledge/mcp) into the workflows you already have.** Point servers at the ticketing, notes, scanners, or internal APIs you use today, in the container or on the host as needed. The agent then calls those tools next to its built-in ones, so Studio plugs into your stack instead of replacing it.

## Perform with it

Operators who already know the craft will love Studio as an IDE for hacking:

- [Editor](/studio/interface/layouts#the-three-layouts) layout, [Speed](/studio/interface/composer#quick-settings) set to the maximum, [Candid](/studio/behavior/personas#writing-one) persona. Be faster, better.
- [Rooms](/studio/interface/rooms) for multiple parallel sessions in the same engagement
- [Kill chain](/studio/behavior/kill-chains) for continuity across the engagement
- The harness and MCPs you taught it: relevance that survives past the first prompt
